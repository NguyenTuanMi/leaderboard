- **Trigger placement is a hard acceptance condition, not a visual suggestion.** The Leaderboard `RouteParser.is_scenario_at_route` checks every interpolated route transform. A trigger is accepted only when at least one point satisfies all three: `dxy = hypot(trigger.x - route.x, trigger.y - route.y) < 2.0 m`; `abs(trigger.z - route.z) < 2.0 m`; and circular yaw error `abs((trigger.yaw - route.yaw + 180) % 360 - 180) < 10 degrees`. Use the absolute vertical difference even though the evaluator implementation's `dz` comparison is one-sided; this is the safer symmetric check.
- Never ask the model to invent trigger coordinates or yaw. Select an integer `route_index` into the dense, interpolated route, then derive the XML `trigger_point` x/y/z/yaw from that exact route transform. Do not use a sparse XML waypoint index as though it were a dense route index. If the dense route or a reliable transform at the selected index is unavailable, do not fabricate one: explain the missing geometry and ask for the route/waypoint data needed.
- Validate every generated trigger against the nearest dense-route transforms using the exact limits above, and report the nearest point's `dxy`, `dz`, and yaw error when it fails. Correct invalid placements before writing the XML. Keep scenarios at least 10 m apart by cumulative route distance (`s`), unless the user explicitly selects a different spacing; distinct trigger coordinates that are close in Euclidean space may still be far apart along the route, and vice versa.
